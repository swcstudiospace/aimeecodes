# v0.3.1 waiter + dedupe — operator checklist

## Env (`/etc/grok-hermes/connector.env`)

```
DEDUPE_ENABLED=1
DEDUPE_WINDOW_SEC=600
```

Optional: `HERMES_JOB_MAX_WAIT_SEC` (default 86400) for waiter timeout.
`HANDOFF_SHARED_DIR` defaults to `/tmp/hermes-handoffs` (jobs under `…/jobs/`).

## Deploy

```bash
cd /root/src/repos/grok-hermes-connector
uv pip install -e . --python .venv/bin/python
.venv/bin/pytest -q
systemctl restart grok-hermes-connector
curl -sS http://127.0.0.1:8788/health   # expect version >= 0.3.1
```

## Behavioral checks

1. After `invoke_skill`, meta should move to `working` with `hermesWorkerPid`
   (not only dispatch PID) once job pid file appears.
2. Status stays non-terminal while `…/jobs/$job.status` says `running`.
3. Second `invoke_skill` with same skill+goal+args within window returns
   `deduped: true` and the original `taskId`.
4. Explicit `idempotency_key` wins over goal text for fingerprinting.
5. Audit may show `outcome: deduped` for collapsed calls.

## Tests

`tests/test_dedupe_waiter.py` — fingerprint stability, active duplicate window,
waiter status-file completion, store.get while status=running.
