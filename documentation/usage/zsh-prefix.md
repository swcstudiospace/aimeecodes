# The : prefix (ZSH)

The ZSH plugin turns your existing shell prompt into a flock control surface. Lines starting with `:` are routed to Aimee; everything else is untouched.

## Install

```bash
aimee setup     # wires the plugin and theme into .zshrc
exec zsh        # reload
```

`aimee setup` is an alias for `aimee zsh setup`. If something misbehaves, `aimee doctor` runs diagnostics on the shell environment.

## How it works

A line starting with `:` is rewritten to an `aimee` invocation. The plugin is modular (`shell-plugin/lib/`): config, syntax highlighting, terminal-context capture, completion, action handlers for auth/config/conversation/git/editor/provider, then the dispatcher and key bindings.

```zsh
: sage how does config resolution handle legacy OMEGA_CONFIG?
:muse plan the importer fix
:aimee implement plans/2026-08-23-importer.md
```

The binary name defaults to `aimee`; override with `AIMEE_BIN` if you alias or rename it. The historical `:omega` spelling remains supported.

## File tagging: paste paths as context

Paste a file path into a `:` line and the bracketed-paste handler wraps it in `@[...]` syntax automatically — path detection and formatting run through `aimee zsh format`, so parsing lives in one tested place. Wrapping only happens on lines starting with `:`; pastes into ordinary commands (`vim /path`) are never mangled.

Tab completion (`^I`) offers interactive fuzzy selection, including file picking via `aimee select file`.

## Key bindings

| Key | Widget | Behavior |
|---|---|---|
| `Enter` (`^M`) | `aimee-accept-line` | Submits `:` lines through the dispatcher |
| `Ctrl+J` (`^J`) | `aimee-accept-line` | Same, for terminals that distinguish |
| `Tab` (`^I`) | `aimee-completion` | Fuzzy completion / file tagging |
| paste | `aimee-bracketed-paste` | Auto-wraps pasted paths in `@[...]` on `:` lines |

Bindings are re-applied after zsh-vi-mode rebuilds its keymaps, so they survive vi-mode plugins. Full list also at [Keyboard shortcuts](../reference/keybindings.md).

## What the dispatcher can do

Beyond plain prompts, the dispatcher recognizes built-in actions from its action handlers:

* **Auth:** provider login/logout, SuperGrok OAuth device login (no API key)
* **Session model:** switch model/provider for the current session only
* **Config models:** pick dedicated models for commit messages and command suggestions (`aimee config set commit/suggest …`)
* **Workspace sync:** init, sync, status, and info for codebase search

Custom commands registered in `.aimee/commands/` are validated against the command list and executed with `aimee cmd execute --cid <conversation>`; a new conversation ID is minted automatically when none exists. Unknown command names are rejected with an error before anything runs.

## Diagnostics

```bash
aimee doctor    # shell environment diagnostics
aimee zsh keyboard
```

Keyboard help text is generated by `aimee zsh keyboard`.
