# CI/CD of Aimee itself

How this repository builds, tests, and releases itself.

## Workflows

Defined under `.github/workflows/`, generated by the `aimee_ci` crate (`gh-workflow`) — **edit the generator, not the YAML** when both exist:

| Workflow | Job |
|---|---|
| `ci.yml` | Build + test + clippy gate |
| `release.yml` | Tagged release pipeline |
| `release-drafter.yml` | Draft notes from merged PRs |
| `autofix.yml` | Automated lint fixes (nightly) |
| `bounty.yml` | Bounty harness runs |
| `coderabbit.yml` | AI code review |
| `labels.yml` | PR labeling automation |
| `stale.yml` | Stale issue/PR management |
| `devcontainer.yml` | Devcontainer validation |

## Quality gates

CI sets `RUSTFLAGS=-D warnings` — **warnings are errors**. The local equivalent before pushing:

```bash
cargo fmt
cargo check -p <crate>
cargo clippy -p <crate> --all-targets -- -D warnings
cargo insta test --accept -p <crate>
```

Known debt: the nightly lint-fix job has been red since early in the project's life (~139 indexing-slicing/double-must-use sites). It does not block merges; don't assume green there.

## Release path

Tagged releases flow through `release.yml` into the distribution matrix: GitHub releases, the NPM binary matrix (`swcstudiospace/npm-aimee-codes`), and the Homebrew tap (`antinomyhq/homebrew-aimee-codes`). Release notes draft from PR history via release-drafter; customer-facing notes can be polished with `/tpl-release-notes`.

## Eval harness

TypeScript evals live in `benchmarks/` with task definitions under `benchmarks/evals/*/task.yml`:

```bash
npx tsc --noEmit
npm run eval
npm run test:bounty     # bounty test suite (.github/scripts/bounty/)
```

## Conventions

Every commit and GitHub comment includes `Co-Authored-By: AimeeCodes <noreply@aimeecodes.dev>` (house rule). Force-pushing shared branches requires explicit request.
